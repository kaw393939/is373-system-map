This was an AI role-play with a separate learner agent and real tools, not a real student study. The learner started without an architecture answer key. ## What was exercised

- Created a GitHub template copy and made a fresh SSH clone. Ran the prepared documentation check and checker tests.
- Used the public [calculator source](https://github.com/kaw393939/is373_ci_cd/tree/4600202bad42da0c5ffb11d83ce8364671293d3d), [hosting source](https://github.com/kaw393939/373_hosting/tree/9d828ad1cf3b72d3c6379e074474683eae0cdd8f) and live calculator. The existing application and hosting repositories were not edited.
- Asked for a live observation and initial request-path prediction before explaining the architecture. Scripted passive probes tested “do everything,” bare approval and the assumption that green Actions means deployment. These probes were deliberate evaluation inputs, not spontaneous learner findings.
- Inspected public behavior and selected read-only host facts. Privileged Docker inspection required a password; no password was requested and that boundary stayed unverified.
- Agreed on an isolated Ubuntu Actions runner, rebuilt the pinned application, checked its reported release identity, confirmed 6 × 7 returned 42 and division by zero returned the documented HTTP 400 error. The [actual run](https://github.com/kaw393939/is373-system-map-trial-1026/actions/runs/40415518240) passed; its helper removes only the trial container/image.

The recreated app is not a recreation of public DNS/TLS, the hosting stack, private persistent state, backups or automatic production deployment. The Mac Docker daemon was initially unreachable and became reachable later; the trial kept its already agreed disposable runner target. It did not repair or replace the Mac's Docker installation.

## Findings and revisions

| Finding | Revision or response |
| --- | --- |
| An independent first reader could not tell the recreation scope before writing its guide. | Agree the executed target and limits before drafting; AI review/checks precede execution. The same reader reread and confirmed the sequence. A design review also clarified that the guide still describes the full existing system, with steps outside the attempted subset labeled source-only/untested. |
| Maintainer QA found that an ignored private file could exist locally, making its Markdown link pass while it would be absent on GitHub. A temporary Git reproduction also caught the same gap through a symlink. | The checker requires both linked names and resolved file targets to be publishable, including directory contents, and rejects empty directory targets. Focused regression tests cover this. |
| A passed CI run could be overclaimed as a deployed or fully restored system. | Keep source expectations, dated runtime observations and actual recreation results separate. The trial checks release identity and records inaccessible layers explicitly. |
| The simulated learner found SPEC still said “result awaiting review” and “learner observation pending” after the successful run and its own release comparison. | Refresh status, next step and result fields from actual evidence before opening the PR. Preserve true gaps; remove stale prompts. |

The first two findings are reviewer/maintainer discoveries, not claims about the simulated learner's experience. The trial's [instructor notes](https://github.com/kaw393939/is373-system-map-trial-1026/blob/main/docs/instructor-trial.md) record the interaction and any additional friction.

## Evidence and limits

The completed trial preserves its own SPEC, recreation guide, learning record, issue/PR and actual CI links. Instructor verification of its final review/merge is recorded after the walkthrough finishes. The disposable repository will be archived recoverably after evidence is preserved.

The revised starter was checked from another fresh SSH clone. Its final check reports zero publication problems and six checker tests pass. These are link/selected-secret-pattern checks, not factual or learning certification. No real student's understanding was measured. ChatGPT desktop's folder-picker flow was not controlled or validated; local file/terminal agent interactions were simulated. A browser review of the real public calculator supplements the learner agent's own HTTP observations and is not relabeled as that learner's browser experience.

For a real class pilot, watch whether students can identify the right local clone, explain one release comparison, and distinguish their attempted recreation from the parts that remain untested. Use that feedback before claiming effectiveness.
