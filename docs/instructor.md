# Instructor notes

This template practices structured AI collaboration through reverse engineering. It complements IS117's design choices and IS218's specified behavior: IS373 explains an operated system and tests how well its documentation supports recreation.

Keep the README as the single student path. The coach reveals concepts when needed, asks one meaningful question and waits. Reuse short contributions to cover the server explanation, delivery/check explanation, own observation and keep decision. Do not add compulsory transcripts, bug-making exercises, quizzes, token quotas or enterprise planning documents. Approval can authorize work; it cannot supply a missing explanation. Report artifact readiness separately from learner evidence.

Students start from different deployed systems. Assess the real boundary and explicit gaps, not whether their architecture matches the class example. Hosting and application delivery may be separate repositories. Do not require a second paid VPS or a destructive production test. Local recreation, public inspection and full isolated restoration are different claims.

The prepared checker uses Python's standard library. It checks local Markdown links and a small likely-secret guard; its tests check that behavior. It cannot verify architecture, certify completion or establish comprehensive secret protection. Keep that limit visible instead of adding a misleading score.

## Evaluating the coaching

Use a separate template copy and fresh SSH clone. Keep completed work out of this unfinished starter. Label simulated learner contributions and scripted stress probes; agent role-play is not evidence of real student learning. Try passive replies such as “do it all” and “it passed” and see whether the coach invites a concrete contribution without repeated quizzing.

Recreation evidence should name what actually ran, where, against which source, and what was not exercised. Never label a fixture as the student's live server. Missing credentials/access remain gaps; a walkthrough of public course repositories cannot establish a student's host state.

Preserve a concise instructor report with actual findings, revisions and evidence links. Keep trial solutions in separate repositories and retire disposable trials recoverably after recording the results; do not point new learners at a solved trial. Archive rather than erase useful evidence. Preserve private material locally outside Git and omit it from published reports.
